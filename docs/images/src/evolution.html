How the process evolved, July to November 2026

17 JUL 2026 · VERSION 1

A deliberately light kit

5 slash commands, 6 rules, a 47-line CLAUDE.md. /implement did one task, then stopped for a human go-ahead.

Built on the same principle as GitHub Spec Kit (github.com/github/spec-kit), lighter and in French.

14 Aug
Tasks chained by default, one dedicated branch per spec, merge only on explicit request
15–16 Aug
Database backup before every /implement, scoped tests per task, full suite at the end
27 Aug
Isolated git worktree only when a concurrent session is a real risk
8 Sep
CI/CD on GitHub Actions: rules start becoming automated checks
15 Oct
Spec lifecycle, DRAFT to CLOSED, verified in CI
16 Oct
Retrospective after every session, and /review split into parallel read-only agents
21 Oct
A process rule born from the action register
28 Oct
Rulebook streamlined, every rule traced to the spec that created it
14 Nov
Optional /brainstorm framing step: current state verified before any spec
Today: the same 5 commands plus an optional framing step. The rules behind them came from 103 specs, and the CLAUDE.md grew from 47 to 112 lines.
